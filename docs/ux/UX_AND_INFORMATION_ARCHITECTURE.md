# UX and Information Architecture

## Design target

Modern, restrained, Google-quality productivity/editor experience: high information clarity without exposing expert complexity prematurely.

## Navigation

Desktop primary: Listen, Create, Studio, Library, Analyzer, Learn. Labs and Settings are secondary.  
Mobile primary: Listen, Create, Library, Files; Studio opens as focused workspace; Analyzer and Learn remain accessible without crowding bottom navigation.

## Simple creator

Screen 1: stimulus type + optional intended use.  
Screen 2: duration.  
Screen 3: beat + actual ear/carrier controls or research template.  
Screen 4: pure/noise/soundscape/imported background.  
Screen 5: headphone/channel check + preview.  
Result: Play, Save, Export, Open in Studio.

Every “purpose” selection explains its evidence status before a user interprets it as a guarantee.

## Studio

Desktop: left library/assets, central timeline, right inspector, compact transport/meter.  
Selection drives inspector. Avoid chains of modal configuration dialogs.  
Automation can be edited graphically and numerically.  
Global command palette + shortcuts.  
Undo/redo and autosave always visible/understandable.

## Precision + approachability

Every frequency control can show:

- Left ear Hz
- Right ear Hz
- Difference Hz
- Center carrier Hz (our defined average)
- percept-range guidance
- source protocol link if research-backed

Beginner view may show center + difference; expanding “Ear frequencies” reveals the exact pair.

## Accessibility

Keyboard-complete editor paths; visible focus; screen-reader labels; high-contrast support; reduced-motion option; scalable text; large touch targets; waveform information also available numerically; visual flicker never auto-starts and is excluded/disabled under reduced-motion preferences unless user explicitly overrides after warning.

## Empty states

Each section teaches one next action: “Drop audio here or Import,” “Create your first session,” “Paste/open a research protocol,” etc. Avoid dashboards full of disabled controls.


## Cloud/community states

Local creation never requires sign-in. Account prompts appear only when the user chooses Sync, Create Share Link, Publish, Review/Rate, Favorite across devices, or Report. The UI distinguishes private local, private cloud, link-shared, and public community visibility. Publication shows asset-rights/provenance checks before submission.

## Visual asset policy

Use the system UI font stack and Lucide icons. The interface may follow modern material/productivity principles but must not copy Google Sans, proprietary Google icons, or pixel-copy another product's trade dress.
