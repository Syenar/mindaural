# BWGen Feature-Parity Acceptance Checklist

First public release must demonstrate tests or screenshots for: custom presets; import/export; WAV render; built-in/imported backgrounds; programmable noise; per-voice beat/volume/pitch/modulation/waveform; parameter tracking; 10+ practical simultaneous voices; multi-segment sessions; delayed/silent start equivalent; background phase shift; background intervals; simultaneous noise+background; background/noise modulation; live edit auditioning; visual stimulation; Legacy 19.2 kHz Light Control; configuration/headphone wizard; context-sensitive help; preset library ratings/reviews/filtering; and light-control waveform/duty-cycle controls.

Obsolete mechanisms such as direct CD playback through a second desktop application are satisfied by documented modern equivalents such as imported audio/media tracks. Legacy `.bwg` binary compatibility is part of the same first-wave parity signoff and requires representative-corpus import, compatible-subset export, field mapping, fuzzing, legacy round trips, and lossless-or-refuse/no-silent-data-loss tests.


## Project-level superiority acceptance

Beyond reference parity, first release must demonstrate: 24+ provenance-clean bundled soundscapes; 30+ first-party curated/research presets; guaranteed WAV/AIFF/FLAC/MP3/Ogg Vorbis/Ogg Opus/WebM Opus import/export matrix as applicable; Supabase immutable share/community workflow; ratings/reviews/forks/moderation; signed `.bbeat` verification; malicious package/parser defenses; offline/local operation without account; responsive mobile editing; analyzer confidence reporting; and exact research provenance/evidence labeling.
